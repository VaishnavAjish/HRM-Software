# HR Module Deep Audit — Critical Findings (2026-08-16)

> Full-depth, read-only audit of every HR submodule (Dashboard, Hiring/Recruitment, Onboarding, Organization, Asset Allocation, Performance Matrix, Exit Management, HR Reports, HR Settings) across frontend, backend, and database. Produced by 11 parallel research passes reading every relevant file in full — not a re-summary of prior docs. See `01-submodule-details.md` for the complete file-by-file writeup this summary is drawn from.

## Read this first — two features are currently broken on render

1. **`HRManagerTab.jsx` (HR Manager's requisitions view) renders `<HrManagerReviewModal>` unconditionally — that component does not exist anywhere in the codebase.** Confirmed by a repo-wide grep: the only occurrence is this one usage, no definition, no import. This throws `ReferenceError: HrManagerReviewModal is not defined` on every render. **The entire HR Manager requisitions tab is currently unusable.**
   `salary-slip-front/salary-slip-front/src/pages/admin/hr/hiring/HRManagerTab.jsx:762`

2. **`CandidateCrmSections.jsx` (Tags/Notes/Communications inside the candidate drawer) calls nine `hrApi.*` functions that were never implemented** in `utils/api.js`: `getCandidateTags`, `getCandidateTagsOf`, `syncCandidateTags`, `storeCandidateTag`, `getCandidateNotes`, `storeCandidateNote`, `deleteCandidateNote`, `getCandidateCommunications`, `storeCandidateCommunication`. This throws synchronously inside a `useEffect` on **every single open of the candidate drawer**, for every candidate. **Tags, Notes, and Communications are entirely non-functional** — only the Documents section (which does have real API methods) works.
   `salary-slip-front/salary-slip-front/src/pages/admin/hr/hiring/CandidateCrmSections.jsx:76-85`

3. **`CandidatePipeline.jsx` (Candidates tab, compact view) uses `<Lock>` without importing it** — a live `ReferenceError` that crashes the compact view for any candidate outside the tab's own stages (i.e. any normal candidate already past shortlisting).
   `salary-slip-front/salary-slip-front/src/pages/admin/hr/CandidatePipeline.jsx:553`

**Recommend verifying all three against the actual running app immediately** — these aren't edge cases, they're mainline paths.

## Security — ranked by severity

| # | Severity | Where | Issue |
|---|---|---|---|
| 1 | **Critical** | `CandidateDocumentController.php` (all 4 methods: `index`, `store`, `review`, `destroy`) | **Zero company scoping anywhere — doesn't even import `ScopesCompany`.** Any authenticated HR user with `hr.candidate.*` permission, from *any* company, can view/upload/approve/reject/delete *any other company's* candidate identity documents (Aadhaar, PAN, passport, bank details) by ID. This is the live controller backing the real Documents UI in Onboarding and the Candidate drawer — not a dead/unused path. Independently confirmed by two separate research passes (Onboarding audit + Hiring backend audit). |
| 2 | **High** | `CandidateAuthController::register()` / `forgotPassword()` | **Confirmed still present, and confirmed worse than previously known: there is no email-sending code anywhere in the file.** Verification and password-reset tokens are the *only* way these flows work — they're returned directly in the JSON response body, not "also" emailed. Anyone who knows/guesses a candidate's registered email can self-verify or take over the account without any access to that email inbox. |

Cross-company asset read/edit/delete by guessing an ID. |

## Data-integrity bugs (not security, but will corrupt real data)

- **Quiz answer-key corruption**: `AssessmentTab.jsx::saveQuiz()` clamps `correct_index` to the post-filter option array length but never *remaps* it. Leaving any option **before** the correct one blank silently shifts `correct_index` onto the wrong answer when blanks are filtered out on save — a quiz can be saved with the wrong answer marked correct with no warning.
- **Offer breakup vs. CTC never validated**: `OfferManagement.jsx::saveDraft()` only checks `designation`/`ctc_annual` are non-empty; nothing enforces the itemized salary breakup actually sums to the declared CTC.
- **Silent duplicate-label data loss** in the same file: two salary-breakup rows with the same label collapse to one via `Object.fromEntries`, dropping the earlier one with no warning.
- **"Forward to Director" is non-functional** in both `ApprovalReviewTab.jsx` and `HRManagerTab.jsx`: the director-selection dropdown state/data is fetched but never rendered, and the actual API call hardcodes `director_id: null` regardless. The entire "pick a specific Director" feature does nothing.
- **"Assign specific HR Manager" is non-functional** in `HRManagerTab.jsx`, same shape: `hr_manager_id` is always submitted as `null`.
- **`JobRequisition::hiringManager()` reads the wrong/renamed column.** A migration (`2026_08_14_010200`) renamed `hiring_manager_id` → `hr_manager_id`, but both columns still exist and are both mass-assignable; the model's `hiringManager()` relation was updated to read `hr_manager_id` while `hiring_manager_id` is still written to in places (`JobRequisitionApprovalService.php:131`) — any code path still relying on the old column silently goes stale.
- **Position/unit mismatch in Promotion/Transfer is only caught at `apply()` time**, not at creation — a request can be fully drafted, submitted, and approved before failing late in the workflow (the transaction does roll back correctly, so no data corruption, but it's a bad late-stage surprise).
- **`revalidateRequest()` in `OrganizationChangeManagementService`** only re-checks `update_unit`/`delete_unit` targets before `apply()` — not `update_assignment` (promotion/transfer) targets, meaning an approved promotion/transfer whose source assignment was deleted/changed in the interim isn't caught before applying.

- **`WelcomePortal.jsx`** (Onboarding) — entire file is hardcoded fake data (fake people, fake tasks, fake itinerary with a literal "Shailesh, NI-24817" example), not routed or imported anywhere. Fully dead.
- **Performance Matrix "PIP" (Performance Improvement Plan) tab is 100% decorative** — no backend model, no migration, no controller endpoint exists anywhere (confirmed by repo-wide search). "Assign PIP" is a toast with no API call; "Graduated"/"Graduation Rate" stat cards are hardcoded `0`/`0%`.
- **Performance Matrix "KPI Templates Library"** — a hardcoded array of 5 fake templates; the "+ Create Template" button actually opens the Goal modal instead, and the setter for the template list is never called.
- **Performance Matrix Export/Download/Promotion-submit/Save-Note buttons** — all toast-only, zero backend calls, across the whole page.

- **`HRManagerTab.jsx` contains an entire second, fully dead copy** of the requisition create/edit form (state, JD-template generation, step-1/step-2 logic, `Field`/`FormSection` components) — leftover from before `RequisitionFormModal.jsx` existed, never rendered, ~150+ lines of pure dead code.

- Roughly 40% of `HrDashboardController`'s JSON response (birthdays, anniversaries, gender/age charts, several card fields) is computed server-side — real DB queries, real cost — but never read by the frontend page that calls it.

## Cross-cutting architectural note

**There is no Eloquent global scope anywhere in this codebase.** Tenant/company scoping is applied entirely by convention — each controller method must remember to call `ScopesCompany::applyCompanyScope()` (list queries) or thread a `whereHas('parent', ...)` through to a scoped parent (child-record queries), with nothing at the model or framework level enforcing it. This is the direct, systemic cause behind nearly every scoping inconsistency found in this audit (#3, #5–9 above): it is trivially easy for a new or edited endpoint to "forget" the scope call, and the codebase currently has many such gaps sitting right next to correctly-scoped sibling methods in the same file. Any future HR endpoint should be checked for this specifically, and — if the team wants a durable fix rather than continuing to find these one at a time — a shared query-scope or model trait enforced closer to the ORM layer would close the whole class of bug at once instead of per-controller.
